# Reador 实际架构

2026-10-08：项目已从静态原型实现为多用户 Web 应用。采用 Next.js / TypeScript 模块化单体、Drizzle ORM 与 PostgreSQL，应用内执行持久化任务，不额外启动队列进程。Docker Compose 提供应用及数据库，当前仅在本机开放端口。

## 代码边界

| 模块 | 实现 |
| --- | --- |
| `src/app` | App Router 页面、统一 API Route Handler、应用任务执行器启动 |
| `src/components` | 注册登录、书库、原文阅读、图谱、问答教学、测验与设置 |
| `src/lib/auth.ts` | HttpOnly / SameSite 会话、来源检查、数据库频率限制 |
| `src/lib/security.ts` | scrypt 密码哈希、AES-256-GCM 凭据加密 |
| `src/lib/schema.ts` / `drizzle` | Drizzle 表定义与有序迁移；部分约束以自定义 SQL 保存 |
| `src/modules/books` | 私有文件保存、PDF / EPUB 解析、原文范围查询 |
| `src/modules/ai` | 三种协议适配、地址校验、超时、有限重试、结构与引用校验 |
| `src/modules/jobs` | 数据库任务领取、租约与心跳、检查点、部分失败及恢复 |
| `src/modules/learning` | 作答、评分修正、补救、最终评级、真实 FSRS 事务 |

前端不读取服务端密钥、数据库连接或私有存储路径。模型调用、解析与评分均在 Node.js 运行时完成。

## 用户与资源隔离

用户资源带 `owner_id`，所有资源查询由服务端登录会话确定拥有者，不能接受客户端指定身份。账号、书籍、章节、原文、模型配置、会话、任务、题目、作答和复习卡分别保存。

数据库通过复合外键保证父子记录属于同一拥有者和书籍，例如 `sources(chapter_id, owner_id, book_id)` 只能引用同账号同书籍的章节。应用层仍验证章节、引用与卡片范围，不依赖外键替代授权。系统不创建共享示例账号，也不在真实书籍上套用预设图谱。

会话 Cookie 仅存随机令牌，数据库存其 SHA-256 摘要；退出时删除会话。密码以随机盐 scrypt 哈希保存。写入请求验证 `Origin`，认证与 AI 操作设数据库频率限制。`COOKIE_SECURE=false` 仅用于本机 HTTP；公网 HTTPS 应启用安全 Cookie。

## 文件与来源

原始文件默认保存到私有 `storage/<owner>/<book-id>.<format>`，数据库记录相对路径；可通过 `STORAGE_BACKEND=qiniu` 切换新导入文件到七牛，数据库保存带空间名的云端对象引用。七牛上传前以 AES-256-GCM 加密原书并绑定对象位置，服务端默认通过七牛官方 S3 签名 API 下载后解密，不依赖自定义下载域名；可选域名模式使用短期签名 URL，浏览器只通过拥有者校验后的原书接口访问。已保存的本地文件保持可读，不自动迁移。Node.js 开发与 Docker 共享该目录，解析和下载均重新定位根目录并拒绝路径越界。下载接口检查拥有者，不把上传文件放进公开静态目录。

PDF 使用固定版本 `pdfjs-dist` 提取文本，优先使用可定位且按阅读顺序排列的书签目录；同页平级书签无法精确分段、目标损坏或没有书签时回退实际页码。每个来源仍保留实际页码。EPUB 在内存中解包，检查展开体积、条目数、加密声明与路径，按 spine 阅读顺序提取纯文本，不执行 HTML 或请求远程资源。优先 EPUB 3 `nav[epub:type=toc]`，其次 EPUB 2 NCX，支持跨文件合并、文件内锚点及父子层级。导航须全部能定位且顺序一致，否则回退正文标题 / 文件分节，标注 `inferred` 与 `origin`；重复文档书名改用编号。纯扫描 PDF 无正文时失败；无文本目录项保留为空，不把下一章正文归给空白项。

上传解析同时提取封面：EPUB 支持 `cover-image`、EPUB 2 `meta name="cover"`、guide 封面页与首节封面页中的本地栅格图片；PDF 用首页缩略图，通过 PDF.js 自带标准字体绘制，避免依赖精简容器的系统字体；全白首页回退文字封面。封面统一转换为最长 480 × 720 的 JPEG，不执行 SVG / HTML 或请求远程资源；图片源限 8 MB、2,000 万像素，失败时回退文字封面。缩略图通过绑定拥有者与书籍 ID 的 AES-256-GCM 加密保存至 `books.cover_cipher`；列表与详情只返回 `hasCover`，`GET /api/books/:id/cover` 检查当前拥有者并禁用缓存。此列由增量迁移新增，已有书籍与学习记录保留。旧书重复上传时可创建幂等的 `cover` 任务补封面，此任务不改章节、来源或调度。

原文以不可变片段保存，包含章节、顺序、实际页码或 EPUB 文件位置。片段上限约 1,400 字符。`chapters.origin / depth / active` 记录结构来源、层级和当前版本；选择父章节取连续子章节范围的并集，避免重复发送来源。长章来源每 500 条分批入库，避免单次 SQL 参数过多。

`POST /api/books/:id/structure` 为旧书创建幂等的非 AI 任务。`books.structure_version` 标识解析结构版本。事务提交前用文本及完整 locator 逐一匹配全部旧来源，任何缺失 / 差异均拒绝更新，不静默生成新 ID。匹配成功后只修改章节归属与顺序，迁移阅读进度；旧章节归档为负位置，并在 `archived_source_ids` 保存更新前的范围，历史会话继续按此范围读取。章节、来源和复习历史均不删除，已有任务快照仍可使用原来源 ID。取消或失败可重试。此入口只允许目录重组，不支持正文替换；全文重解析仍需显式来源版本与重定位机制。

## 模型配置与适配

按账号管理多组模型配置，每个账号最多一个默认项。服务端可读取 `.env` 的 DeepSeek / GLM 配置，以 `ENV_MODEL_ACCESS=shared / owner / disabled` 控制可用账号；没有个人默认项时使用当前账号获准访问的服务器默认模型；两者都不可用时返回可理解的配置错误，上传、目录 / 封面解析和阅读不依赖模型。环境默认生成任务的 `agent_id` 为空，但仍保存加密配置快照并关联拥有者。系统设置可将环境配置另存为当前账号的个人默认项，保留独立配置。API Key 经 AES-256-GCM 加密入库，不回传前端。密钥加密参数来自环境；任务保存加密配置快照，修改默认模型不会改变已排队任务。

官方模型预设统一位于 `src/modules/ai/presets.ts`，前后端共用。新建 / 切换厂商预填核对日的通用模型及协议，可手动修改；切换第三方时清空模型 ID 以填写网关别名。当前预设与官方出处见 README。已保存 Agent、环境变量和任务快照不自动升级；预设不是实时模型目录。

- Chat Completions：`/chat/completions`、`messages`、Bearer 认证及 `choices` 解析。
- Responses：`/responses`、`instructions` / `input`、`max_output_tokens` 及 `output` 解析。
- Messages：`/messages`、`system` / `messages`、`x-api-key` / `anthropic-version` 及内容块解析。

期望最大输出的前后端默认值为 1,000,000 tokens，范围 256–1,000,000；新建、切换厂商与环境模型共用该默认值。已核实的官方主机与型号按 `min(配置值, 官方输出上限)` 发送，设置页展示实际发送值；未知型号与网关按填写值发送并提示自行核实。配置值与上下文窗口不同，不改变正文批次范围。已保存个人配置及任务快照保留原预算。响应体边界为 `max(2,000,000, 1,000,000 + 实际输出上限 × 24)` 字节，兼顾 JSON 转义开销并保持内存有界；超时仍由原配置控制。

Base URL 为完整接口前缀，拼接时不额外添加版本路径。不同协议分别构建输入与解析结果，不用换地址冒充兼容。Temperature 留空时省略；某些模型对参数和结构化输出另有限制，需要真实连接测试确认。

调用验证 HTTPS、拒绝携带 URL 凭据与查询参数、解析所有 DNS 结果并拒绝私有地址，通过固定解析结果建立连接，不跟随重定向。响应大小、超时与重试次数有限；只对网络错误、429 和服务端错误重试，不在错误中回显密钥或模型原始正文。私有网络仅可由开发环境显式启用。

书籍、用户答案和会话历史只作为数据传入，无模型工具调用。应用要求 JSON，并用 Zod 严格校验；逐字引用必须属于服务端选定原文。评分要点必须完整、不重复、分数不超权重，由服务端计算总分。语义是否忠实仍需人工评估。

## 生成任务与范围

任务基于 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取，记录运行令牌和租约，执行过程中发出心跳。进程退出后，过期租约可重新领取。正文在解析时已切成最多约 1,400 字符的片段，`batchSources` 再按原文顺序组合为每批最多 10,000 字符，执行时显式恢复批次中的来源顺序；上传及封面任务不调用模型，点击生成才发送正文。字符限制不包括提示词和 JSON 开销，不代表精确 token 预算。每批独立生成，保存成功结果与失败原因；部分失败不会冒充完整成功。

状态为 `queued → running → ready / partial / failed`，可取消未结束的 AI 任务；晚到结果通过状态和令牌校验，不能覆盖取消状态。失败 / 部分失败可重试，保留成功检查点；终态图谱和题目写入事务，任务幂等键防止重复创建。

图谱先验证结构、端点和引用，再编译受限 Mermaid。引用校验区分来源超出当前批次与摘录不逐字匹配，错误提供位置，不回显原文。只有图谱引用失配触发一次额外重生成，将相同来源范围和错误位置传入；第二次仍严格校验，失败批次不发布，取消后不重生成。网络重试和输出截断规则保持不变。总览显示前 20 个概念，完整数据分批查看；跨批次不自动合并同义词，避免无依据连线。手动源码使用 strict Mermaid 渲染，禁止指令、HTML 和外链；修改后移除原图来源对应关系。

概念图谱入口采用版本卡片，详情地址使用 `?view=graph&book=<书籍 ID>&graph=<任务 ID>`（也支持产物 ID），路由支持刷新与浏览器前后退。无结果的历史任务在列表中折叠；批次错误按消息去重，并列出原批次序号。生成记录、来源细节和范围说明默认折叠。阅读页不显示任何图谱任务记录；详情页保留重试失败批次和取消进行中任务入口。图谱日期按账号时区显示。

问答与教学共享同范围会话，支持诊断、提示、讲解和理解检查。扩大到整书必须由用户主动选择，新范围创建 / 恢复对应会话，避免带入范围外历史。长范围使用基础关键词检索选取片段，明确检索范围；当前没有向量检索。聊天与教学消息持久保存。

## 检测与复习

生成题目时保存知识目标、题面、参考答案、权重及来源，并为目标建立独立复习卡。获取题目和到期列表不返回参考答案，提交后才可读取。

开始正式学习即创建当前调度轮次的作答草稿；同一卡、同一版本只允许一份正式作答。返回原文、下载原书或调用讲解时，服务端为未提交草稿记录辅助状态，客户端不能抹去。提交答案后保留原始作答，评分失败可以恢复。用户修正评分时保留原评分、理由与修正时间；已提交评级后不能追溯修改排期。

讲解后的换题保留同一知识目标，记录为补救练习，不能更新 FSRS。失败、无法回忆或辅助作答不能按独立成功评级。一次高分不推断整书掌握。

FSRS 使用固定 `ts-fsrs@5.4.2`，开启库默认学习步骤并关闭 fuzz，使测试可复现；调度函数接收明确当前时间。最终评级在事务中锁定作答与卡片，检查调度版本，原子写复习日志及新状态。复习日志对作答设唯一约束；重复评级返回同一记录，不重复排期。题目、卡片状态、作答与日志分别保存，新图谱不会重置复习历史。

时间以 PostgreSQL `timestamptz` 保存，界面按用户设置的 IANA 时区显示。到期列表直接按保存的时间计算，保留全部后续复习任务，不依赖通知后台。

## 部署与后续边界

本机使用 Compose PostgreSQL 命名卷及私有文件目录。数据库迁移自动执行；开发时也可单独运行迁移。上传目录权限通过本机 UID / GID 映射处理。

`.github/workflows/publish-image.yml` 在推送 tag 时校验对应提交已进入 `main`，再使用现有 Dockerfile 构建 amd64 / arm64 镜像并发布到 GHCR。`compose.production.yaml` 提供拉取镜像的独立服务端配置，数据库与本地原书使用命名卷，运行时从 `.env.production` 注入配置；不自动更新远程服务器。具体发布、权限与恢复流程见 [服务端部署指南](deployment.md)，真实发布及部署验收仍需在 GitHub 和目标服务器执行。

尚未实现邮件验证、密码找回、OCR、PDF 原版式、语义检索、跨批次概念合并、已就绪原书重新解析 / 来源重定位，以及公网运维设施。Linux 公网部署须另行配置 HTTPS、反向代理、可信 `APP_ORIGIN`、安全 Cookie、注册策略、容量和备份，不宣称当前本机验收覆盖这些能力。

预设来源（2026-10-08）：[OpenAI 官方快速入门](https://developers.openai.com/api/docs/quickstart)、[Claude API 总览](https://platform.claude.com/docs/en/api/overview)、[智谱 OpenAI 兼容](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)、[DeepSeek 首次调用](https://api-docs.deepseek.com/zh-cn/)。实际模型可用性以账户权限和连接测试为准。

七牛 S3 区域与端点依据 [官方服务域名说明](https://developer.qiniu.com/kodo/4088/s3-access-domainname)，使用固定 AWS SDK v3 执行签名请求；密文大小受限，错误不回显 SDK 原始内容。显式启用的模型 DoH 依据 [Cloudflare JSON DNS 说明](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)，不会放宽公网地址检查。
