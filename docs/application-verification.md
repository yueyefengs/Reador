## DeepSeek 图谱输出预算修复（2026-10-08）

真实故障任务使用官方 Chat Completions 的 `deepseek-v4-flash`，配置输出上限 4,096 token。对原失败批次复现时 HTTP 为 200，但 `finish_reason=length`、最终回答长度为 0，供应商 usage 显示输出预算用于思考，未形成最终 JSON。原适配器忽略结束原因，将截断 / 空回答统一报为 JSON 无效。DeepSeek 官方文档确认默认开启思考，JSON 输出也需足够的输出预算：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)。

修复只在官方 DeepSeek 主机、已知双模式型号的结构化 Chat 调用中显式关闭默认思考，不改写用户保存的型号、上限或密钥，也不向第三方网关注入该参数。图谱请求精简为最多 6 个核心概念、8 条关系、短定义和逐字短引用；范围及来源校验保持不变。适配器分别识别三种协议的输出上限状态、仅思考、空回答、无效 JSON 与结构不匹配；截断响应即使碰巧是完整 JSON 也不发布，推理字段不作为最终答案使用。连续两个批次出现输出契约错误时停止剩余调用，按实际结果标记 failed / partial；显式重试恢复失败与未执行批次，成功批次不重复。只有取消操作才标记 cancelled，失败不会自动冒充取消。

- `npm test`：54 项通过。回归用例在修复前出现 5 项失败，修复后全部通过，覆盖默认思考参数、精确主机匹配、保留上限、三种协议截断、空回答诊断和有效 JSON。
- `npm run test:integration`：73 项检查通过、24 次本地协议模拟调用。新增连续两批截断后暂停、剩余批次不调用、明确错误原因、不发布半份图谱及显式重试恢复。
- 真实复核：同一本书的原失败批次（154 个原文片段）、同一 `deepseek-v4-flash` 与 4,096 token 上限，修复后生成 6 个节点、5 条关系，结构、逐字引用与端点校验通过。原 cancelled 任务及其结果均未改动，没有恢复或重跑全部 9 批。此项验证修复后的输出契约与引用有效性，不代表整书图谱或语义质量已全面验收。
